# العناوين والمشاركة — المرحلة 8

المعاينة تحدّث عنوان المتصفح ووصف الصفحة وOG/Twitter باللغة الحالية، وتستخدم صورة اللوجو الأصلي ضمن ملفات الويب. في صفحة المشروع يستخدم العنوان والملخص من المنشور فقط. لوحة الفريق عنوانها عام ولا ينسخ مدخلات الطلب الخاصة إلى metadata. صفحة غير منشورة تعرض حالة غير متاح.

الويب يستخدم روابط hash كما ثبت في مرحلة 3. تحديث metadata بعد تشغيل Flutter يفيد الوثيقة المفتوحة، ولا يولد HTML مستقلًا لكل مشروع عند الخادم؛ زاحف مشاركة لا يشغل التطبيق أو يتجاهل الجزء بعد # قد يرى بيانات YOGEN العامة فقط. لا ندعي معاينة منفصلة ناجحة على واتساب/فيسبوك أو فهرسة كاملة.

أبقي noindex,nofollow للمعاينة، ولا أضع دومينًا مخمنًا أو canonical للإنتاج. صورة OG في HTML المصدر نسبية حاليًا لأن دومين الإطلاق لم يحدد؛ تجهيز عنوانها المطلق عند الاستضافة جزء من التسليم. تغيير النص أو نشر المشروع ينعكس على الوثيقة المفتوحة دون تعديل كود، مع بقاء حدود الزواحف هذه.

[Flutter Web FAQ الرسمي](https://docs.flutter.dev/platform-integration/web/faq) يوضح حدود استخدام Flutter للمحتوى الذي يحتاج الفهرسة. [Firestore الرسمي](https://firebase.google.com/docs/firestore/manage-data/transactions) يشرح الكتابات الذرية وgetAfter المستخدمين لحفظ الطلب والإيصال معًا.
