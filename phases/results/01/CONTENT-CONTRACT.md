# عقد محتوى المشاريع والشركة

المرحلة 1 — 9 أكتوبر 2026. عقد وظيفي للاستخدام في تصميم النماذج وتنفيذ التحقق لاحقًا، وليس مخطط Firestore برمجيًا.

## حالات البيانات

تستخدم بطاقات الحصر والقالب أربع حالات: **متوفر** من المستخدم أو مصدره، **يحتاج المستخدم** لمعلومة لا نعرفها، **يحتاج تحقق** لترجمة أو تصنيف أو رابط مستنتج لم يؤكد، و**اختياري** لبيان يمكن إغفاله. الاختيارية لا تبرر نشر قيمة مخمنة؛ إذا أُدخل الحقل يتحقق منه.

حالة المعلومة مستقلة عن دورة النشر: مسودة / منشور / مؤرشف. كذلك حالة الاستخدام الفعلي مستقلة: مستخدم فعليًا / تجريبي / شخصي أو سابق للفريق. وصف «أغلب الأعمال حقيقية» لا يملأ قيمة كل مشروع تلقائيًا.

## قواعد الحفظ والنشر

1. المسودة تقبل أي نقص وتظهر للفريق فقط؛ يُحفظ ما أُدخل فعلًا دون ملء تلقائي بوقائع مخمنة.
2. النشر يحتاج الحقول الإلزامية باللغتين، وتصنيفًا وحالة استخدام ومساهمة وغلافًا صالحًا، وروابط الصفحة الفريدة.
3. أي وسيط مختار للعرض يجب أن يكون جاهزًا ومربوطًا؛ يمكن استبعاد وسيط اختياري فشل رفعه ثم إعادة التحقق. لا يُنشر مرجع ملف معلق أو مفقود.
4. الرابط والسنة والتقنيات والنتائج والفيديو ليست شروطًا للنشر. لا تمنع بيانات أعضاء الفريق العامة المؤجلة نشر مشروع موثق المساهمة.
5. يعرض نقص النشر بجوار الحقل ولكل لغة، ويظل المحتوى قابلًا للإكمال. لا توجد رسالة نجاح عند فشل الحفظ أو مهلة غير محسومة.
6. تعديل منشور ينشئ مسودة منفصلة منطقيًا عن النسخة العامة. تظهر النسخة الجديدة بعد اكتمال النشر؛ آلية الحفظ والنسخ تثبت في 4.
7. الاختيار «منشور» لا يساوي اختيار «مستخدم فعليًا». يمكن نشر تجربة أو عمل شخصي موثق مع نسبته الصحيحة.

حاليًا جميع بطاقات الحصر مسودات مستندات غير جاهزة للنشر؛ لا توجد بيانات عامة منشورة في Firebase بهذا العمل.

## بيانات الفريق العامة

الملفات فارغة حتى يدخلها المستخدم من الأدمن. العدد الأولي ثلاثة لا يفرض حدًا على الإضافة.

| البيان | قاعدة الظهور |
| --- | --- |
| الاسم والدور بالعربية والإنجليزية | مطلوبان لإظهار الملف؛ اسم الشخص يمكن كتابته بصيغته التي يختارها |
| النبذة والصورة والروابط | اختيارية؛ النبذة المعروضة تتوفر باللغتين، والصورة المعلوماتية لها وصف بديل مناسب |
| ترتيب وظهور الملف | الملف الجزئي محفوظ مخفيًا؛ لا كروت بأسماء وهمية أو صور بديلة تقدم كأشخاص حقيقيين |
| حساب الدخول ودور الإدارة | سجل مستقل؛ لا يمنح الملف العام صلاحية ولا يتأثر حساب الدخول بإخفاء الملف العام |

إذا لم توجد ملفات كاملة ظاهرة، يخفى قسم الفريق، وتبقى نبذة الشركة متاحة. لا تنشأ ثلاثة أعضاء وهميين لملء التصميم أو المحتوى الحقيقي.

## بيانات الشركة والتواصل

| البيان | قاعدة الحفظ والعرض |
| --- | --- |
| الاسم والشعار | YOGEN والأصول المرفقة؛ لا يعاد تعريف الشركة باسم مشروع Firebase |
| نبذة وخدمة وعناوين | نصوص باللغتين؛ لا ينشر قسم ناقص لغة أو ادعاء إضافي غير موثق |
| واتساب | قناة اختيارية؛ الرقم والتحويل إلى رابط صحيح يتحققان لاحقًا؛ لا رقم افتراضي |
| البريد التجاري | قناة اختيارية؛ يتحقق من شكله وعمله؛ لا بريد تجريبي عام |
| روابط اجتماعية ودومين | اختيارية؛ تحقق قبل الإظهار، واتجاه مناسب داخل العربية |
| وجهة نموذج الطلب | مدخلة تشغيل في 8: تخزين خاص أو إرسال/قناة محددة وفق القرار؛ لا نجاح وهمي |

عدم إدخال التواصل يسمح بالحفظ والتصميم والمعاينة. أزرار القنوات الغائبة مخفية، ولا زر واتساب أو mailto فارغ. زر طلب مشروع لا يقدم إرسالًا غير متاح؛ قبل الإطلاق يلزم مسار استقبال صالح ومختبر. تعديل رقم أو بريد من الأدمن يحدث الروابط في الموقع دون إعادة بناء التطبيق.

## الوسائط

الملفات في Drive؛ Firestore يحفظ المعرف والاسم والحجم وMIME والمجلد والروابط ودور الملف والترتيب والأوصاف ووقت الرفع ومرجعه. مصدر عرض الصورة داخل الموقع مستقل عن رابط فتح Drive. لا Base64 دائم داخل Firestore، ولا اعتماد على لقطة المشاريع المجمعة كغلاف نهائي لكل مشروع. صلاحية مشاركة ملف Drive لا تتغير تلقائيًا بأرشفة المشروع.

القواعد هنا تنفذ وتختبر في 3–8؛ نجاح مراجعتها في 1 لا يعني نجاح الرفع أو الحفظ أو النشر في تطبيق فعلي.
