# تقرير إغلاق المرحلة 3 — YOGEN

## المخرجات

أنشئ أساس Flutter للمنصات الست، بالعربية والإنجليزية وRTL/LTR وLight/Dark وتفضيلات محفوظة، ومسارات وصفحات تحقق مستقلة للبيانات والوسائط والرسم المجسم. بني Web release وWindows release وAndroid debug. هذا أساس تقني؛ واجهات الموقع الكاملة وإدارة المشاريع تنفذ في مراحلها.

سجلت تطبيقات Web/Android/Apple داخل Firebase Portfolio، `portfolio-14d15`. ثبت دخول وخروج Email/Password وكتابة/قراءة Firestore فعليًا من Flutter Web. القواعد التي كانت ترفض الجميع محفوظة، ونشرت قاعدة تجربة محدودة لحساب واحد ومسارات phase03_checks فقط؛ مسارات الإنتاج لا تزال مرفوضة. لم تنشأ حسابات أعضاء YOGEN أو صلاحياتهم النهائية.

أنشئت مجلدات YOGEN في Drive وApps Script مستقل ونشره بإصدار 4. المستخدم فعّل API وأكمل موافقة Google. الصور والفيديوهات في Drive، وFirestore يحفظ مراجعها؛ لا تخزين Base64 في قاعدة البيانات. رفع PNG عربي من file picker ظهر داخل بطاقة ومعرض Flutter بلا دخول Google وفي Chrome/Edge والوضعين وبعد التحديث.

فيديو MP4 تجريبي 5 MiB رفع فعليًا ثم شغل داخل Flutter Web عبر قراءة محدودة من Apps Script وBlob. طريقة Drive preview لم تثبت التشغيل؛ حفظ فشلها. الأحجام 20/50/100 MiB رفضت محليًا قبل القراءة، ولا ادعاء بدعمها. حد التجربة 5 MiB مقترح للنسخة الأولى؛ ليس الحد الرسمي للخدمات ولا ضمانًا لكل نوع ومدة.

نموذج 3D أصلي في Dart يعرض عمقًا وإضاءة ومنظورًا ومدارًا ودورة 360° بالتمرير، مع الإيقاف وتقليل الحركة والبديل الثابت. نقل معرض المشاريع وكامل تصميم المرحلة 2 إلى Flutter في 6، والأداء المتكامل في 9.

## الاسترجاع والمتابعة

مصدر المرحلة 2 محفوظ ولم يستبدل. يمكن إيقاف خادم التحقق المحلي دون مساس بالتصميم أو موارد السحابة. ملفات البناء قابلة لإعادة التوليد من المصدر وpubspec.lock. لا يوجد commit Git لهذه المرحلة لأن المجلد ليس مستودعًا بعد.

قواعد Firestore السابقة في `firebase/firestore.before-phase03.rules`؛ استعادتها عند طلب الرجوع توقف تجربة الكتابة لأن الأصل يرفض الجميع. يلزم مقارنة أي قواعد أحدث قبل النشر، ولا تستبدلها عميانيًا. Apps Script له إصدارات محفوظة؛ يمكن إعادة توجيه نفس النشر إلى الإصدار السابق عند طلب الرجوع، مع ملاحظة أن إصدار 3 لا يقدم بديل الفيديو في 4.

ملفات التجارب وحسابها والموارد العامة مسجلة في config وchecks. عند انتهاء الحاجة إليها تعزل أو تزال بعملية مستقلة تتحقق من المعرفات؛ لا حذف تلقائي للمجلد الجذري أو محتوى المستخدم. لا تنسخ التجارب كأعمال منشورة، ولا تعيد رفع ملف عندما المطلوب إعادة حفظ مرجعه فقط.

## معالجة بيانات الفحص وحدود الأدوات

أخرج فحص CLI سابق تفاصيل جلسة OAuth، وظهر جزء منها في نتيجة أداة؛ أبلغ المستخدم وقتها. نقل الملف الخام إلى `.runtime` واستبدل التقرير العام بالحالة فقط، وأضيف الاستبعاد. هذا لا يمحو نتيجة الأداة القديمة ولا يدعي إلغاء الرموز. لا ترفع `.runtime` أو ملفات الأسرار، والمجلد الحالي ليس مستودع Git بعد.

أوقف التحكم في Chrome على Windows تلقائيًا بسبب تعذر التحقق من عنوان المتصفح. لم تكرر هذه المحاولة؛ إعداد الخدمات والفحوص المحلية تم عبر CLI/موصل Drive واختبارات المتصفح المعزولة للتطبيق المملوك. موافقة Google أجراها المستخدم بنفسه.
